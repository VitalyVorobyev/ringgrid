# Migrating from 0.16 to 0.17

## Decoding: exact matches against the target's codewords

0.17 decodes a marker only as an exact match (in any rotation) of one of the
codewords **the target's cells carry**, samples the code band at an estimated
sub-sector phase, and no longer tries the complement (inverted) word. The
reasons and measurements are in
[ADR-027](../decisions/027-phase-aligned-exact-decode.md).

**Config** (`DetectConfig.advanced.decode`, JSON, Python `DecodeConfig`):

| Removed | Why / what to do instead |
|---|---|
| `max_decode_dist` | Only distance 0 is accepted; a tolerance only admitted noise. Remove the key. |
| `min_decode_margin` | An exact match on the target's codewords has no ambiguity to gate. Remove the key. |
| `min_decode_confidence` | Same. Remove the key. |
| `codebook_profile` | Was a read-only copy of the target's profile; decoding now reads the target directly. Set the profile on the target (`CodedRingSpec::codebook_profile`). |

`samples_per_sector` now defaults to **8** (was 5) and also sets the number of
sub-sector phases tried; values are clamped to `[2, 32]`.

Unknown keys in a config overlay are ignored, so an old config file still
loads; the removed keys simply have no effect.

**CLI** (`ringgrid-dev detect`): `--decode-min-margin`, `--decode-max-dist` and
`--decode-min-confidence` are removed.

**Python**: the `DetectConfig` aliases `decode_min_margin`, `decode_max_dist`
and `decode_min_confidence` are removed, as are the four `DecodeConfig`
fields above.

## Diagnostics: `DecodeMetrics`

`ringgrid::diagnostics::DecodeMetrics` (JSON `decode`, Python
`DecodeMetrics`):

| Before | After |
|---|---|
| `observed_word`, `best_id` | unchanged |
| `best_rotation: u8` | `rotation: f32` — continuous, `[0, 16)` sectors: printed sector `j` starts at parametric angle `(j + rotation)·2π/16` on the fitted outer ellipse. `floor(rotation)` is the old cyclic shift relative to the phase-aligned sampling grid. |
| `best_dist`, `margin`, `decode_confidence` | removed — every decode is an exact match |

The decoded word is sampled dark-on-light only; a marker printed light on
dark no longer decodes.

## ID correction (fallback path)

Every decode is now an exact match, so a marker with its own decode is always
a strong seed. Two `IdCorrectionConfig` fields follow (JSON
`advanced.id_correction`, Python `IdCorrectionConfig`):

| Before | After |
|---|---|
| `seed_min_decode_confidence` | renamed `seed_min_confidence` (same default 0.7). It compares **marker confidence**, and only for markers that carry an ID without their own decode. Rename the key; the old key is ignored. |
| `confirm_by_consistency` | removed with its pass: it promoted untrusted non-exact decodes, which no longer exist. Remove the key. |

## Detection output on oblique views and blurred large rings (ADR-026)

No API change; detection output changes in ways a caller that pins counts,
confidences or snapshots will notice.

### More markers, same labels

The outer fit now follows strongly eccentric (oblique) rings exactly, and
completion refits anchored rings whose centre correction failed. Every
target kind reports more markers; on the precision harness the reported
IDs, board positions and labels that were right stay right, and no new wrong
one appears. Outer-ellipse centres (`circle_refinement = None`) move by a few
tenths of a pixel where the refit edge points changed; photometric centres
by thousandths.

### Photometric confidence

When a photometric fit replaces a marker's centre, the sharpness term of its
`confidence` is measured against the ring's size (`max(3 px, 0.1875 r)`
instead of 3 px). Rings up to 32 px across are unaffected; larger blurred
rings get a higher confidence and pass `min_confidence` more often. A
threshold tuned on large photometric rings under 0.16 admits more of them.

### Grid labels are checked against ring shapes

A grid labeling whose homography does not predict the fitted ring shapes is
re-indexed to the lattice basis that does, or refused when none does. A
strongly oblique plain view that 0.16 reported in the relative frame with
sheared labels now anchors; a labeling no basis explains yields no labels
(coded targets fall back to the decode-anchored path).

### Adaptive detection

`detect_adaptive` ranks its candidates by the markers with a board position
that the output contract would report, and skips the code-band scale probe
for plain targets without a diameter hint. The selected candidate can differ
from 0.16 on any target.

**What to update:** nothing in code. Re-bless detection snapshots and revisit
any `min_confidence` tuned for photometric centres of large rings.

## Verification, photometric confidence and adaptive joins (ADR-028)

No API change; detection output changes.

- **Geometric verification** keeps markers it removed on strongly oblique
  views with large rings (its local test no longer mistakes perspective for
  a displacement) and removes labelled markers it cannot vouch for: no
  labelled neighbour, while uncorrected lens distortion has loosened the
  global residual threshold past half a cell pitch.
- **Photometric configurations** are verified after the photometric stage,
  on the refined centres. `FitMetrics::h_reproj_err_px` from finalize is the
  pre-photometric residual; the reported markers passed the gate on their
  refined centres.
- **Photometric confidence**: an accepted photometric centre's `confidence`
  is evidence × outer fit × border × `1/(1 + (σ / 0.1 px)²)` (σ from its
  `center_cov`) × ring-relative sharpness — rim coverage and inner-edge
  agreement no longer enter it. Edge-fitted centres are unchanged. Large,
  blurred or partly unsampled rings with a good photometric fit now pass
  `min_confidence`.
- **`detect_adaptive`** returns the best candidate joined with the anchored
  markers other candidates found at cells it lacks, in the same board
  placement; its homography is refit over the union.

**What to update:** nothing in code. Re-bless detection snapshots; revisit a
`min_confidence` tuned on photometric centres.

## Photometric confidence from the predicted centre error (ADR-029)

No API change; photometric `confidence` values change.

- An accepted photometric centre's `confidence` is evidence × outer fit ×
  border × `1/(1 + σ / 0.03 px)`, `σ = √((tr center_cov + b²)/2)`, `b` the
  blur-gradient bias (`1.24 · σ_blur · |∇σ_blur|`) the fit does not correct.
  The ring-relative sharpness factor of 0.17-dev is gone.
- Values are lower for most photometric centres (rtv3d median 0.48 → 0.40)
  and spread with the centre's precision: blurred but precise centres keep
  more of their confidence, imprecise ones lose more.
- `DetectedMarker::center_cov` is unchanged; the bias enters only the
  confidence.

**What to update:** retune a `min_confidence` or review-tool threshold set
on photometric confidences; re-bless detection snapshots.
