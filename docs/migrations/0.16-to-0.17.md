# Migrating from 0.16 to 0.17

## Decoding: exact matches against the target's codewords

0.17 decodes a marker only as an exact match (in any rotation) of one of the
codewords **the target's cells carry**, samples the code band at an estimated
sub-sector phase, and no longer tries the complement (inverted) word. The
reasons and measurements are in
[ADR-027](../decisions/027-phase-aligned-exact-decode.md).

**Config** (`DetectConfig.advanced.decode`, JSON, Python `DecodeConfig`):

| Removed | Why / what to do instead |
|---|---|
| `max_decode_dist` | Only distance 0 is accepted; a tolerance only admitted noise. Remove the key. |
| `min_decode_margin` | An exact match on the target's codewords has no ambiguity to gate. Remove the key. |
| `min_decode_confidence` | Same. Remove the key. |
| `codebook_profile` | Was a read-only copy of the target's profile; decoding now reads the target directly. Set the profile on the target (`CodedRingSpec::codebook_profile`). |

`samples_per_sector` now defaults to **8** (was 5) and also sets the number of
sub-sector phases tried; values are clamped to `[2, 32]`.

Unknown keys in a config overlay are ignored, so an old config file still
loads; the removed keys simply have no effect.

**CLI** (`ringgrid-dev detect`): `--decode-min-margin`, `--decode-max-dist` and
`--decode-min-confidence` are removed.

**Python**: the `DetectConfig` aliases `decode_min_margin`, `decode_max_dist`
and `decode_min_confidence` are removed, as are the four `DecodeConfig`
fields above.

## Diagnostics: `DecodeMetrics`

`ringgrid::diagnostics::DecodeMetrics` (JSON `decode`, Python
`DecodeMetrics`):

| Before | After |
|---|---|
| `observed_word`, `best_id` | unchanged |
| `best_rotation: u8` | `rotation: f32` — continuous, `[0, 16)` sectors: printed sector `j` starts at parametric angle `(j + rotation)·2π/16` on the fitted outer ellipse. `floor(rotation)` is the old cyclic shift relative to the phase-aligned sampling grid. |
| `best_dist`, `margin`, `decode_confidence` | removed — every decode is an exact match |

The decoded word is sampled dark-on-light only; a marker printed light on
dark no longer decodes.

## ID correction (fallback path)

Every decode is now an exact match, so a marker with its own decode is always
a strong seed. Two `IdCorrectionConfig` fields follow (JSON
`advanced.id_correction`, Python `IdCorrectionConfig`):

| Before | After |
|---|---|
| `seed_min_decode_confidence` | renamed `seed_min_confidence` (same default 0.7). It compares **marker confidence**, and only for markers that carry an ID without their own decode. Rename the key; the old key is ignored. |
| `confirm_by_consistency` | removed with its pass: it promoted untrusted non-exact decodes, which no longer exist. Remove the key. |
